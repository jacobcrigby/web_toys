# AGENTS.md — coaster-track-quiz

## What this is

A teaching quiz that trains you to identify **roller coaster manufacturers from the track** —
the spine cross-section, how the rails attach, the cross-tie pattern — rather than from a
famous ride's layout or its trains.

Each question shows a tight close-up of track and offers four manufacturers. The reveal names
the specific visual tell, explains why each wrong option is wrong, and links out to RCDB and
the photograph's Wikimedia Commons page. Manufacturers you get wrong come back more often.

Deployed to `https://jacobcrigby.github.io/web_toys/coaster-track-quiz/`.

## Architecture

```
main → controller
controller → ui, quiz, data, storage, rng
ui   → data (types + formatters), quiz (types only)   ; never imports controller
quiz → data, rng        data → nothing        rng → nothing
```

`src/quiz/` and `src/data/` are **pure** — no DOM, no `Date.now()`, no `Math.random()`. All
randomness goes through the seeded `src/rng.ts`, which is what makes the engine testable.
`src/ui/` is the only layer that touches `document`, and it receives an `Actions` callback
object rather than reaching back into the controller.

```
src/
  main.ts             boot
  controller.ts       owns AppState; every mutation goes through commit(); image preloading
  state.ts            AppState, hash routing
  storage.ts          localStorage 'coaster-track-quiz:v1' with a field-level repair pass
  rng.ts              seeded mulberry32: next / int / pickWeighted / shuffle
  data/
    types.ts            Manufacturer, TrackFamily, Tell, Coaster, CoasterImage, Attribution
    manufacturers.ts    HAND-WRITTEN — the eight makers
    track-families.ts   HAND-WRITTEN — tells, confusableWith, DISCRIMINATOR_ORDER, PAIR_NOTES
    coasters.generated.ts  GENERATED by scripts/emit-dataset.mjs — do not hand-edit
    dataset.ts          indexes and lookups
    attribution.ts      utm stripping, Artist sanitising, credit formatting, rcdbUrl
  quiz/
    leitner.ts   boxes and BOX_WEIGHTS       progress.ts  Progress + applyOutcome + summarize
    select.ts    target and coaster choice   decoys.ts    pedagogically weighted wrong answers

  ui/
    dom.ts  render.ts  quiz.ts  reveal.ts  image.ts  guide.ts  stats.ts  pips.ts

```

## Key types

`TrackFamily` sits between manufacturer and coaster, and that is the important modelling
decision. **The visual tell belongs to the track family, not the company.** Vekoma's 1980s
catalogue track and their post-2015 track look nothing alike, and B&M is only genuinely
confusable with *modern* Vekoma. Hanging tells off the manufacturer would force one blurred
paragraph per company and destroy the pedagogy.

Decoy explanations are **derived** from the families' own `Tell` phrases via
`contrastFamilies`, which walks `DISCRIMINATOR_ORDER` and returns the first aspect the two
families describe differently. `PAIR_NOTES` then hand-writes only the ~10 genuinely hard pairs.
With sixteen families there are 120 pairs, most of them trivial, and hand-written text would go
stale the moment a tell was edited. The guide renders the same `phrase` strings, so the reveal
and the reference can never drift.

## Conventions

- TypeScript strict, plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `verbatimModuleSyntax`. Every source file carries `// SPDX-License-Identifier: Apache-2.0`.
- Zero runtime dependencies. Plain DOM, plain CSS, no framework.
- Tests co-locate as `src/**/*.test.ts`.
- Generated = facts, URLs, attribution. Hand-written = pedagogy (`manufacturers.ts`,
  `track-families.ts`, `blindAlt`, `note`). Re-running the emitter never clobbers prose.
- A pick in `picks.json` may pin `name`, `park`, `country` or `opened` when Wikidata is wrong
  or silent; the pin always beats the fetched fact. The emitter warns about every gap it had
  to leave, so a clean `pnpm data:emit` run means no reveal will show a missing park or year.

## Deliberate deviations from the monorepo conventions

1. **It touches the network at runtime.** The repo-root `AGENTS.md` says projects have no
   backend and no telemetry, and that remains true — this app makes **no `fetch` or XHR calls
   at all**. But it does hotlink photographs from `upload.wikimedia.org` via `<img>`, which is
   a documented exception alongside `daylight-map`'s CARTO tiles.
2. **The photographs are third-party CC-licensed content.** The code is Apache-2.0; the images
   are not ours and are not vendored. Attribution is a licence obligation, and
   `dataset.test.ts` machine-checks that every image records an author, a licence, and a
   Commons file page. Any new image must go through `pnpm data:emit` so this is captured.
3. **A committed generated source file** (`coasters.generated.ts`). Justified by the
   zero-runtime-API-calls requirement; the emitter sorts deterministically so diffs stay small.
4. **A content-integrity test suite.** `dataset.test.ts` asserts things about data, not code.
   The leak guard and the attribution check are the only things standing between a curation
   slip and either a spoiled question or a licence violation.
5. **Attribution is phase-split** — see below.
6. **Scheduling uses an ordinal question counter, not wall-clock time** — see below.

## Gotchas

- **Attribution is deliberately split by phase.** Author and licence show at all times, which
  satisfies the CC licences. The *Commons file-page link and the image description are
  withheld until the reveal*, because Commons file names and descriptions nearly always
  contain the coaster's name and would hand over the answer. `alt` follows the same rule:
  `blindAlt` during the question, the real description afterwards. This looks like an omission
  if you do not know why it is there.
- **`lastAskedAt` is an ordinal question counter, not `Date.now()`.** Sessions are short and
  bursty, so spacing by question number is the right model, and it keeps the whole engine free
  of clock and timezone dependence. Do not "fix" it to a timestamp.
- **Storage repairs rather than resets.** The manufacturer roster is data and may grow. Adding
  a maker must not throw away real learning history, so `loadProgress` drops unknown ids,
  defaults missing ones to box 1, and clamps an out-of-range box instead of bumping the schema.
- **Image URLs must contain no `?`.** `dataset.test.ts` enforces it, and `ui/image.ts` relies on
  it: a retry cache-busts with a `#` fragment. The Commons API appends `utm_*` params to every
  URL it returns, so the emitter strips them.
- **Thumbnails stay on `upload.wikimedia.org`.** The Commons API now returns thumbnail URLs on
  `thumb.wikimedia.org`. The old host serves the identical path, `dataset.test.ts` pins it, and
  `index.html` preconnects to it, so the emitter rewrites the host rather than churning every
  URL in the dataset. If `upload.wikimedia.org` ever stops serving thumbs, change all three.
- **Wikidata coaster items are inconsistently modelled.** The park may be `location` (P276) or
  `part of` (P361), and P276 is often a *city*; the opening date may be P1619, P571 or P580;
  relocated rides carry two parks and two countries; labels go stale (RCDB 17030 is still
  labelled by its working title "Mako", but opened as Emperor). The emitter prefers candidates
  typed as an amusement park, reduces multi-valued fields deterministically, and warns — fix the
  rest with a pin in `picks.json`, never by editing the generated file.
- **`ui/image.ts` retries once silently.** Commons answers a burst with a 429 that clears in a
  second or two, so the first failure of each source is retried after 1.5 s before any error
  UI appears. The tests advance fake timers past that window; a new "it errors" test has to
  fail twice.
- **Never `innerHTML` anything from Commons.** `extmetadata.Artist` is an HTML fragment;
  `sanitizeArtist` reduces it to text and `ui/dom.ts` only ever sets `textContent`.
- **Curation cannot be automated, and filename search does not work.** Searching
  `deepcategory:"…" track` returns 6 hits for Mack and 8 for Gerstlauer, and several of those
  are wide shots. The pool has to be looked at.
- **Wikimedia rate-limits bulk fetching.** Firing thumbnail requests back to back returns HTML
  429 pages, which will be written straight into a `.jpg` if you do not check. `scripts/lib/http.mjs`
  throttles to ~1 req/s, retries with backoff, and verifies image magic bytes. This affects
  curation only — a browser loading one photo at a time never hits it.
- **Hybrid conversions are a curation trap.** A Commons category for an RMC conversion often
  still holds photographs of the *wooden coaster it replaced* (Storm Chaser's category is full
  of pre-conversion Twisted Twins shots). Check what you are actually looking at.
- **Some Wikidata RCDB ids are wrong.** At least one duplicate `Twisted Cyclone` item carries a
  two-digit id. `pnpm data:verify` checks that every RCDB link resolves, but it cannot tell you
  the link points at the right ride.
- `vitest run` exits non-zero with zero test files. Vitest defaults to the `node` environment;
  DOM tests need `// @vitest-environment jsdom` at the top of the file.
- `base` applies in dev too — the dev URL includes `/web_toys/coaster-track-quiz/`.

## Accuracy of the teaching content

`track-families.ts` is a best-effort synthesis, not an engineering reference. The
strong tells (B&M's box spine, Arrow's round pipe and ladder ties, RMC's I-Box on timber,
GCI's steel strip versus Topper's wrapped channel) are solid. The finer discriminations —
Mack versus modern Vekoma, Gerstlauer versus Intamin — are judgement calls about proportion
and fabrication, and are the places to correct first if something reads wrong.
